Odds Provider API Keys

Primary provider is required; the two backups are optional. All keys are saved locally to a .env file in the project folder -- never sent anywhere except each provider's own API.

Primary: The Odds API

Get a free key at the-odds-api.com. 500 credits/month free, ~1 credit per game for HR props.

Backup 1: ParlayAPI

Get a free key at parlay-api.com. 1,000 credits/month free, single-call player-props endpoint (cheaper per-lookup than The Odds API).

Backup 2: SharpAPI

Get a key at sharpapi.io. Rate-limited free tier rather than credit-metered, but only 2 sportsbooks included on the free tier.

Validate MLB Stats API

Checks a live pull against the official MLB Stats API: probable pitchers present and mapped to a valid handedness, and whether starting lineups have been confirmed yet for each game.

Validate Statcast / Baseball Savant

Highest-risk data source in this project -- Savant has no official API, only a CSV export that can change without notice. This checks whether the columns we expect actually come back, and whether the values look sane (right numeric range, not garbage).

Daily HR Alpha Score Report

The full pipeline: ingest games/pitchers/hitters/weather/odds, score every player, rank by HR Alpha Score. Stage 1 (Watch List) runs before lineups post and includes bench players (can't know starters yet). Stage 2 (Final Rankings) only scores confirmed starters and includes real betting edge if an Odds API key is saved. Odds are reused from cache (30 min) unless you force a refresh -- re-running a report on the same day won't burn extra API quota by default.

Historical Tracking & Backtesting

Every Stage 2 report you generate is automatically saved. Record actual results here after games finish, then run the backtest summary to see hit rate and ROI by Alpha Score tier -- the real answer to whether the scoring weights mean anything.

Sub-metric breakdown diagnostic

For every scoring sub-metric across all four categories: what % of saved rows actually had data for it ("% Rows w/ Data"), vs what % of its max points it captures on average. A sub-metric near 0% data is structurally unreachable right now (not ingested anywhere yet) -- that's different from a sub-metric that has data but is just scoring low. Sorted worst-first within each category.

Benchmark range calibration audit

Raw bulk stats inspector

Investigates row-count discrepancies (e.g. ISO's 149 vs 565+ for other hitter metrics from the calibration audit) by showing exactly what MLB Stats API's bulk endpoint returns, before any filtering. Distinguishes "the API only sent us this many rows" from "our code dropped rows after receiving them" -- same discipline that resolved the fly-ball units question.
